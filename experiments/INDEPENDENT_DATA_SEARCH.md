# Independent football data for possession-spell evaluation

Research snapshot: 2026-10-29. The new-data search found no unrestricted, ready-made full-match broadcast dataset that combines synchronized tracking with dense, independently adjudicated home/away/dead-ball (`H/A/D`) intervals. There is, however, one concrete full-match sample from a new provider source available now for event-silver checks and a blind annotation pilot: SoccerTrack v2 match 117093. It is a fixed full-pitch panorama, not a television broadcast, and its event labels do not equal possession spells.

The Metrica organizer match was not used, annotated, or opened for this search. Match 117093's metadata identifies a separate Japanese university fixture, outside the professional Sportec/Metrica/SkillCorner matches already exposed in the project. The small downloaded sample is stored in ignored `data/independent/soccertrack_v2/117093/`. The [acquisition manifest](results/soccertrack_v2_acquisition_manifest.json) records verified source links, file sizes, hashes and the remaining large assets.

## Ranked shortlist

### 1. SoccerTrack v2, match 117093 — usable now for independent event-silver and manual gold

The project's [official page](https://atomscott.github.io/SoccerTrack-v2/) links a public [Google Drive mirror](https://drive.google.com/drive/folders/1N2Qx2qkFgRtpbHitl2Vh6sLVYGgqkWwn?usp=sharing) and declares the video and annotation data CC BY 4.0 with attribution in its [data license](https://github.com/AtomScott/SoccerTrack-v2/blob/main/LICENSE-DATA). The Hugging Face copy asks users to accept an information-sharing condition; the official Drive mirror is sufficient for this sample and required no form or NDA.

I fetched and read the 479,053-byte BAS JSON and both small ball NPZs through the public Drive mirror. The match metadata identifies **University of Tsukuba vs University of Tsukuba - B**, 2023-11-25 at 10:00 JST. The roster metadata has 41 player entries with blank personal names. This identity is disjoint from the professional Sportec/Metrica/SkillCorner fixtures already exposed in the project. The direct folders for the [match video](https://drive.google.com/drive/folders/19JQ9Uq1doemU8PlGDs5oPlNTpi6L0xnS), [BAS labels](https://drive.google.com/drive/folders/1XkK4FWekdIb4as3wpgPO4hbp7JbyD_ni), [GSR player tracks](https://drive.google.com/drive/folders/1B9lb-a3H7H136g-1BSyaBUJ4gJED6U6s), and [raw metadata and roster](https://drive.google.com/drive/folders/15VW5QVQQTTEJusmzSYGEfmv2zFPFsyyi) are publicly listed.

The video release contains both complete 25-fps panorama halves (3,346,094,631 and 3,481,770,525 bytes). This is full-pitch BePro footage from fixed/panoramic cameras, not a TV edit with ordinary broadcast cuts. Per-frame player GSR files are listed separately at 2,712,752,520 and 2,830,326,845 bytes. The GSR is player tracking; ball data is a separate, small NPZ per half. I did not download the multi-gigabyte videos or GSR files.

The actual BAS artifact is `{"match_id", "fps", "clock", "actions"}`. Its 2,252 `actions` have `gameTime`, `label`, `position`, `frame`, `team`, and `player_id`. Counts are PASS 951; DRIVE 889; HIGH PASS 150; OUT 80; CROSS 45; THROW IN 39; BALL PLAYER BLOCK 30; SHOT 23; PLAYER SUCCESSFUL TACKLE 20; FREE KICK 17; GOAL 5; HEADER 3. Teams are recorded as `left`/`right`. For example, the first action is PASS by `right`, player `467351`, at half 1, 640 ms, frame 17. These are event points, not state intervals. A few labels imply local semantics—e.g. a successful tackle is defined as winning possession, `Out` marks the ball leaving play, and `Free Kick` is a restart—but there is no `H/A/D` or continuous possession field. The [BAS format page](https://github.com/AtomScott/SoccerTrack-v2/blob/main/docs/format-bas.md) documents the 12 action classes.

There is a consequential clock discrepancy to resolve before joining any events to frames. In the actual Drive JSON, the first half-2 event is at `2 - 0:00`, 753 ms, frame 20; the final one is at `2 - 46:46`, 2,806,273 ms, frame 70,158. This is half-local timing and matches the artifact's `clock` description. The current [GitHub loader](https://github.com/AtomScott/SoccerTrack-v2/blob/main/src/data_utils/soccertrack_v2.py) instead says the released positions are absolute from match start and should subtract a nominal 45-minute offset. The raw XML period metadata has its own frame and clock origins. Treat the exact Drive file and loader as inconsistent; verify time alignment against the half videos and raw period metadata before using event labels as anchors.

The ball NPZ contains `frame`, `x`, `y`, `status`, and scalar `y_flipped`; the halves have 67,625 and 70,475 rows. `status` histograms are first half `{0: 18,438; 1: 28,750; 2: 17,183; 3: 3,254}` and second half `{0: 18,025; 1: 22,242; 2: 26,570; 3: 3,638}`. The public format pages do not define these status codes. More importantly, the dataset maintainers' [Drive release changelog](https://drive.google.com/file/d/1jPUUWbqWI5HQuXfZuEHsL54UyVBSv5Ma/view) confirms that ball positions are interpolated from annotated event anchors, following straight segments at constant speed between anchors. Do not treat them as independent observed-ball input or use their status counts as a measured-visibility rate. They remain useful for checking file integration; corrupting them does not create independent observed-ball evidence.

The raw `player_nodes.csv` is a second event-oriented table: 2,581 rows across the two halves, with event time/period, provider event strings, team/player IDs, and normalized locations. It has no continuous team-control state. Use it as extra event-silver only after its origin and event-time alignment are reconciled with BAS; do not present it as independent possession gold. The [GSR format page](https://github.com/AtomScott/SoccerTrack-v2/blob/main/docs/format-gsr.md) also carries a release warning that actual player JSON differs structurally from its advertised schema, so stream and validate any future GSR ingest rather than assuming the documented parser is correct.

**Recommended use:** label one fixed ten-minute slice of the first-half panorama independently with two football-literate annotators, then extend to the full half if the pilot's agreement and adjudication effort are acceptable. Freeze a model-blind `H/A/D/X` interval CSV with boundary uncertainty, confidence, and reason; keep BAS, provider events, ball NPZ, and all model outputs hidden until labels are locked. `H`/`A` means last controlled team; `D` means dead play; `X` is genuinely unresolved. Preserve duels, deflections, loose balls, stoppages, and any filmed gaps. Then use BAS/provider events as event-silver and audit anchors, not as the spell target. This gives immediate possession-spell gold for a new match, but only tests transfer to full-pitch panoramic amateur footage—not television broadcast missingness or camera cuts.

### 2. Alfheim / Simula — accessible full-match video and sensor tracking; possession labels are reported but not shipped

The [Alfheim release](https://datasets.simula.no/alfheim/) provides two complete 2013 Tromsø IL matches with stitched full-pitch video and 20-Hz ZXY wearable tracking for the ten home outfield players (no goalkeeper or away-team tracking). Video is split into three-second segments; matching player sensor logs are available. The terms restrict use to non-commercial research and prohibit player re-identification or performance profiling.

The open [PLOS paper](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0251970) reports that researchers manually recorded controlled-possession changes in VoTT and synchronized attack/defence/out-of-play phases to the home tracking. Its possession convention is useful: a player needs enough control to adjust the ball's direction; a momentary opponent touch does not switch possession; out-of-play or an infringement ends it. However, the downloadable inventory does not list that phase-label file, so it is not a ready-made gold target. A third Alfheim match has roughly 40 minutes and some short clips with manually marked ball pixels, but it is not a full-match ball track. These data can support a manual annotation pilot or a non-broadcast auxiliary experiment; home-only wearables and fixed camera arrays limit transfer to broadcast tracking.

### 3. SoccerNet-GAR / legacy SNGAR — strongest true-broadcast event-silver, but access is gated

The current [SoccerNet-GAR card](https://huggingface.co/datasets/OpenSportsLab/SoccerNet-GAR) describes synchronized PFF/Gradient broadcast video and tracking for 64 World Cup 2022 matches, with 87,939 trained-annotator action points across ten classes and reported ball tracking in 93.4% of the card's frames. These are point labels with event team/activity information, not continuous possession intervals. The current GAR video and `tracking-full` branches are 144-frame windows per action—about 4.8 seconds—so they cannot expose genuine long live-ball gaps.

The [legacy whole-match tracking release](https://huggingface.co/datasets/OpenSportsLab/SNGAR-Action-Spotting-Tracking-deprecated) describes 64 continuous full-match tracking tables at about 29.97 Hz (11,849,815 frames total), with 48 World Cup matches plus 16 further matches, paired with a separate broadcast-video release and the same 87,939 action points. Event labels were derived from the PFF/Gradient hand-annotated event stream and quality-checked against video/tracking. This is new event-silver relative to the project's currently exposed Sportec/Metrica/SkillCorner data and is useful for event-led experiments, even though the event/tracking publisher is the same PFF/Gradient source. The legacy Hugging Face page redirects to a SoccerNet Raw HQ access request and personalized NDA; do not use it unless project owners separately obtain and review those terms. The current short clips are not a substitute for the long-gap test.

### 4. PFF/Gradient 2022 World Cup release — best direct broadcast tracking lead remains pending

PFF's [official release announcement](https://www.blog.fc.pff.com/blog/pff-fc-release-2022-world-cup-data) advertises tracking for all 64 matches (`{game_id}.jsonl.bz2`), one events file, metadata and PDFs, available through an access form. The release does not itself establish rights to matching video or dense H/A/D state labels. It is the same underlying provider/source as SoccerNet-GAR, not another independent provider.

The existing request to Gradient remains pending, based on the project owner's Oct 25 email asking for access and ML-training-license permission; do not send a duplicate request. PFF's current [general terms](https://www.pff.com/terms) restrict ML/AI use and computer-vision evaluation or improvement unless applicable supplemental terms expressly authorize it. Treat the request and data as unusable until a response clarifies the actual research/model-evaluation scope and matching-video rights.

### Lower-value routes

* **SoccerNet-Tracking / SoccerNet-GSR clips:** useful for short action or player-tracking clips, but no dense possession state and insufficient continuous footage for long gaps; raw video is gated by a researcher/non-commercial NDA.
* **Driblab Open Data:** its [public README](https://github.com/driblab/open-data) describes ten 10-Hz broadcast tracking files with ball and camera projection, but the public repository currently lists documentation rather than the data files, has no matching videos or event/possession labels, and no explicit data license was found. Do not use without file access and rights confirmation.

## Minimal acquisition and annotation plan

1. Use match **117093**, first half, as the new panorama pilot. Its public Drive listing is already verified. Download the 3.346-GB first-half MP4 only when ready to annotate; keep the locally saved BAS JSON hidden from annotators. The event JSON, both ball NPZs, raw metadata XML, raw player-node CSV, and padding file have already been saved under the competition repository's ignored `data/independent/soccertrack_v2/117093/` directory. No video or multi-gigabyte GSR was downloaded.
2. Select a continuous ten-minute interval before viewing model outputs or event proposals. Two annotators independently label H/A/D/X intervals from the panorama alone. Use the metadata only to identify the two teams; do not give annotators event or tracker-derived possession suggestions.
3. Record `source_sha256, period, start_pts_s, end_pts_s, label, boundary_earliest_s, boundary_latest_s, confidence, reason, annotator_id`. Preserve separate raw annotations; adjudicate only after both passes, document disagreements and unresolved coverage, and freeze the label protocol before expanding to a full half.
4. After labels are frozen, align BAS and `player_nodes.csv` events against the video using per-half XML timing, and audit the actual BAS-vs-loader clock discrepancy. Score possession spell F1 only on adjudicated continuous labels. Report BAS/provider event metrics separately. Exclude the reconstructed ball NPZ from inference or observed-ball evaluation.
5. Use the sample to test possession-state logic, interval evaluation, timestamp handling, and annotator agreement. Keep TV-broadcast missingness claims reserved for a full-match PFF/SNGAR release with approved matching-video rights or another genuinely broadcast source.
